Project Flow:



games.csv : It contains the rows of Basketball game data. Most import columns are : Text id, eg. S001, Generated text: The summaries that were generated by traditional LLMs/NNs.



shared\_task.jsonl : This file contains the "ground truth" (Box score) in Rotowire format. One row contains one reference/ ground truth for each reference generated.



token\_lookup.yaml : Blueprint for tokenization. It contains doc\_to\_sent and sent\_to\_doc (Reverse) levels.



###### **PIPELINE:**



During the data loading/Preparation step: we have dataframe: Games.csv + shared\_task.jsonl



Prompt Construction: Right now we are using the simple human instructions that injects : text id, i.e. eg. S001, story: Generated text from games.csv, game\_data ("Ground\_truth/ Reference") from shared\_task.jsonl



It injects strict instructions generated by a PydanticOutputParser to force the LLM to return a strict JSON array. Also it tell LLM to not just randomly guess the token, give what exact token is (Rules given inside the build prompt function in pipeline).



The Prompt is fed up to the LLM, and LLM generates the output as JSON string: After that we take the output and pass it to the extract\_json function that extract the JSON string from output, as it confirms that JSON string is taken and not the extra conversional text from LLM.



we get (Regex output) : \[ { "TEXT\_ID": "S001", "SENTENCE\_ID": 1, "ANNOTATION\_ID": 1, "TOKENS": \["Friday"], "TYPE": "NAME", "CORRECTION": "Wednesday", "COMMENT": "Game was on Wednesday" } ]



Then we convert the JSON string into the structured and reliable python object. This is done by passing result into parser that results the python object:

\- After we get the list of the token ("Error"), We create the document token map for generated texts in Games.csv file.

It creates a dictionary (doc\_map). Example: { 1: {"sentence\_id": 1, "token\_id": 1, "token": "The"}, 2: {"sentence\_id": 1, "token\_id": 2, "token": "Boston"}... }



After we have the document map for generated text and Python object of the LLM Results: we will pass doc\_map and List of tokens from python object to find\_token\_span function, what this function does is :



It searches the doc\_map sequentially. When it finds a sequence of tokens in the map that exactly matches the LLM's tokens, it grabs the starting doc\_token\_id and the ending doc\_token\_id.

Output Mapping: DOC\_TOKEN\_START = 6, DOC\_TOKEN\_END = 8.



At this final stage of pipeline : it saves all the results, which includes the Annotation part +  "DOC\_TOKEN\_START": start,  "DOC\_TOKEN\_END":   end, "MODEL": model\_key and "TIME\_SECOND": time taken

###### **EVALUATION PIPELINE:**



Now the LLM guesses, we must compare them against human-annotated (gmsl.csv)



Script has function (create\_mistake\_dict):  The primary purpose of create\_mistake\_dict is to ingest raw mistake data whether from the human-annotated Gold Standard or the LLM's predictions and transform it into a standardized, highly searchable nested Python dictionary. As it parses each row, it rigorously validates the token indices against the master YAML lookup to ensure perfect mathematical alignment, **prevents duplicate spans from corrupting the data  if an overlap is detected, the script raises an Exception that instantly stops the loop,** and critically, converts each mistake's token range into a mathematical set (e.g., {220, 221}).

Once this mistake dictionary is created, it is pass to **check\_token\_id** with the text\_dir, text dir contains txt files, where each file is one generated summary. So based on token ids present in mistake dict for each tokens and tokens\_ids, for each token in text dir, it matches and guarantees the alignment, basically  ensuring no alignment errors occurred during tokenization.



From here we have two step evaluation: MIstake level and token level evaluation:



Mistake level:

Once the tokens are verified, then we match Gold standards with submitted LLM results, it is done with match\_mistake\_dict function: outputs a nested dictionary that records exactly which human-annotated Gold Standard (GSML) mistakes were successfully caught by the LLM, and which ones were missed. It groups these true/false results by the category of the mistake.



Outputs:

If there are 3 different mistakes in that sentence, it forces the LLM's giant highlight to match with only one mistake, and then deletes it. The LLM misses the other two.
